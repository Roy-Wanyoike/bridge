# go-typescript — one contract, a Go service and a TypeScript client

Generates **both** a Go module and a TypeScript package from the single
`catalog.bridge` contract, so a Go backend and a TypeScript frontend compile
against exactly the same shapes.

## Files

| File | What it is |
| --- | --- |
| `catalog.bridge` | The contract: package `catalog.v1` (products, availability, paging) |
| `demo.mjs` | Compiles the contract and writes `generated/{go,typescript}` |
| `generated/` | Output directory (gitignored — regenerate any time) |

## Run

From the repository root, build the workspace once:

```sh
npm install
npm run build
```

Then, from this directory:

```sh
node demo.mjs
```

Expected output (deterministic file lists and bytes):

```text
go:
  go.mod
  types.go
  enums.go
  validate.go
  services.go
typescript:
  package.json
  tsconfig.json
  src/types.ts
  src/enums.ts
  src/validate.ts
  src/services.ts
  src/index.ts

Written to examples/go-typescript/generated/ (gitignored).
Both packages speak the same wire format: the Go service and the TypeScript client stay in lockstep because they compile from the same IR.
```

## The integration story

1. **Contract first.** `catalog.bridge` is reviewed like any other API change.
2. **Generate both sides.**

   ```sh
   node demo.mjs          # writes generated/go and generated/typescript
   # or regenerate every example at once:
   node scripts/generate-all.mjs   # from the repository root
   ```

3. **Go side** — `generated/go` is a module (`module catalog/v1`) with
   `types.go`, `enums.go`, `validate.go` (constraint checks for `@length`,
   `@min`, `@max`, …) and `services.go` (the `Catalog` server trait). Verify
   it compiles with `go vet ./... && go build ./...` — no Go toolchain here?
   Run `scripts/verify-go.sh` locally (it skips gracefully) and let CI, which
   has Go installed, enforce it.

4. **TypeScript side** — `generated/typescript` is a package with typed
   models, enums, validators and re-exports via `src/index.ts`. Verify it
   type-checks with the workspace TypeScript:

   ```sh
   scripts/verify-ts.sh   # transpiles every generated .ts, asserts 0 errors
   ```

5. **Ship changes safely.** Before publishing a contract change, gate it with
   the compatibility engine — see [compatibility](../compatibility) and
   [COMPATIBILITY](../../docs/COMPATIBILITY.md).

## What to notice

- `Money.amount` is `int64` in Go but `number` in TypeScript — the mapping
  table (and the 2^53 caveat) is documented in
  [IDL_REFERENCE](../../docs/IDL_REFERENCE.md#primitives).
- `tags: list<string>` becomes `[]string` / `string[]` on the same JSON wire.
- Generated headers read `Code generated by bridge DO NOT EDIT.` — output is
  byte-deterministic, so regenerated code never produces diffs churn.
